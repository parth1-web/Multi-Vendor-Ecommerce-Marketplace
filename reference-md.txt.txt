## Complete Master Development & AI Coding Reference — Next.js Edition

> **CSS Utility Framework:** ❌ Tailwind not used

# 1. Project Vision

The goal is to build a **production-grade multi-vendor e-commerce marketplace** similar in concept to large marketplace platforms such as Amazon or Daraz.

Unlike a basic e-commerce application where products belong directly to one store, this system supports:

- Multiple sellers
- Multiple customers
- Seller stores
- Seller-specific products
- Inventory management
- Product variants
- Product search
- Category hierarchy
- Shopping cart
- Wishlist
- Checkout
- Multi-seller order splitting
- Payments
- Payment webhooks
- Refunds
- Seller commissions
- Reviews
- Coupons
- Notifications
- Real-time updates
- Analytics
- Admin management
- Audit logs
- Background processing
- Redis caching
- SEO-friendly storefront pages

The project should demonstrate the ability to build a **large real-world business platform**, not simply a CRUD application.

---

# 2. Why Next.js

The frontend is intentionally upgraded from a basic React/Vite architecture to **Next.js** because this marketplace contains many public pages where SEO, routing, metadata, performance, and scalable frontend organization matter.

Next.js will be used for:

```text
Public marketplace pages
Product pages
Category pages
Seller/store pages
Search pages
Customer dashboard
Seller dashboard
Admin dashboard
Authentication pages
SEO metadata
Open Graph metadata
Sitemap
Robots configuration
Image optimization
Server-rendered/static public content where appropriate
Client-side interactive features where required
```

The application should use the **Next.js App Router**.

Do not treat Next.js as merely React with a different start command.

Use Next.js features intentionally.

# 3. Frontend Rendering Strategy

Use a hybrid rendering model.

## Server Components

Prefer Server Components for:

```text
Public homepage
Product detail pages
Category pages
Seller/store pages
Static informational pages
SEO-sensitive content
Initial product discovery
```

Benefits:

```text
Better SEO
Smaller client JavaScript
Better initial rendering
Improved performance
```

---

## Client Components

Use Client Components only where interactivity requires them.

Examples:

```text
Cart interactions
Wishlist buttons
Product quantity selectors
Checkout forms
Filters with client interaction
Modals
Dropdowns
Notifications
Real-time SignalR
Zustand state
React Hook Form
Interactive charts
```

Use:

```tsx
"use client";
```

only when required.

Do not make the entire application a Client Component unnecessarily.

# 15. Important Next.js Authentication Rule

Authentication must ultimately be enforced by the backend.

Next.js frontend checks are only for user experience.

Never rely on:

```text
Frontend route protection
Hidden buttons
Role checks in React
```

as the actual security mechanism.

The ASP.NET Core API must enforce:

```text
Authentication
Authorization
Resource ownership
Seller isolation
```

---

# 16. Next.js Middleware

Use Next.js middleware only for lightweight routing decisions where useful.

Possible uses:

```text
Redirect unauthenticated users
Redirect obvious role mismatches
Protect dashboard routes at the UI layer
```

Do not put complex business authorization inside middleware.

Backend authorization remains authoritative.

---

# 17. Authentication Token Strategy

Recommended architecture:

```text
Browser
   │
   ▼
Next.js
   │
   ▼
ASP.NET Core API
```

For browser authentication, prefer a secure architecture that minimizes JavaScript exposure of long-lived credentials.

Possible strategy:

```text
Short-lived access token
+
Secure refresh mechanism
+
HttpOnly cookie where appropriate
```

Never store sensitive long-lived refresh tokens in:

```text
localStorage
sessionStorage
Zustand persistence
```

unless there is a specific, justified architecture requiring it.
